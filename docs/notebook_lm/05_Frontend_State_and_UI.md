# هيكلة واجهة المستخدم وإدارة الحالة (Frontend & UI Architecture)

## 1. التقنيات الأساسية (Core Stack)
الواجهة الأمامية لنظام Septimus OS مبنية بالكامل باستخدام:
- **Next.js 16 (App Router)**: Server Components وTurbopack وبنية `proxy.ts`
  الحديثة لحماية المسارات.
- **React (TypeScript)**: كتابة مكونات قوية وآمنة من حيث الأنواع (Type-safe).
- **Zustand**: إدارة الحالة العالمية (Global State) لخفتها وسرعتها مقارنة بـ Redux.
- **Tailwind CSS**: تنسيق الواجهات بشكل سريع وفعال.
- **مكونات محلية بأسلوب shadcn/Base UI**: المكونات المطلوبة محفوظة في
  المستودع؛ لا توجد حاجة إلى CLI إنتاجي أو اعتماد شامل غير مستخدم.
- **Framer Motion**: مكتبة الحركات الدقيقة (Micro-animations) لتوفير تجربة مستخدم ديناميكية وراقية.

## 2. إدارة الحالة (State Management - Zustand)
بدلًا من تمرير الخصائص (Prop Drilling) المعقد، نعتمد على `Zustand` لإنشاء مخازن (Stores) مخصصة لكل جزء من النظام:
- **`useAppStore`**: المخزن الرئيسي لإدارة بيانات المستخدم الحالي، الـ Workspace النشط، وصلاحيات النظام.
- **`useChatStore`**: مخصص لإدارة رسائل القنوات، الغرف العامة، وإشعارات القراءة.
- **`useToastStore`**: لإدارة التنبيهات المنبثقة (Toasts) في جميع الشاشات.

## 3. دعم اللغات والاتجاهات (RTL / LTR)
تم بناء النظام ليكون ثنائي اللغة (Bilingual) من اليوم الأول لدعم الأسواق العربية والعالمية:
- **Context API (`LocalizationContext`)**: يدير تغيير اللغة حياً (On-the-fly) بدون إعادة تحميل الصفحة.
- **Tailwind `rtl/ltr` variants**: تم تكوين `Tailwind` بخصائص منطقية (Logical Properties) مثل `ms-` (margin-start) و `pe-` (padding-end) ليقلب التصميم تلقائياً من اليمين لليسار بناءً على اتجاه الصفحة `<html dir="rtl">`.

## 4. نظام المكونات (Component Design System)
جميع مكونات النظام مصممة بنمط `Glassmorphism` الحديث مع ألوان حيوية وحركات تفاعلية:
- **`GlassCard`**: مكون الحاويات الأساسي الشفاف بخلفيات ضبابية `backdrop-blur`.
- **Modals & Dialogs**: يتم عرضها دائماً فوق طبقة ضبابية، وتم استبدال وظائف المتصفح الافتراضية (مثل `window.confirm`) بمكونات React مخصصة لتجنب مشاكل المتصفحات الحديثة.
- **الودجت (Widgets)**: مكونات لوحة القيادة مبنية بنمط "البطاقات الذكية" التي تجلب بياناتها بشكل غير متزامن.

## 5. الحماية في الواجهة (Frontend Security & Auth)
- يعتمد النظام على `src/proxy.ts` في Next.js 16 للتحقق من وجود Cookie الجلسة
  `septimus_session` قبل فتح صفحات التطبيق المحمية.
- الجلسة HttpOnly وSameSite=Strict؛ صلاحيتها الفعلية وإبطالها يُتحقق منهما في
  backend-core وليس في JavaScript أو localStorage.
- عند غياب الجلسة يُعاد المستخدم إلى شاشة الدخول في المسار `/`.
