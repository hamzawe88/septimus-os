# التحديث اللحظي وأحداث الويب (Realtime & WebSockets)

## 1. محرك الـ Realtime (Centrifugo & NATS)
بدلاً من الاعتماد على مكتبات WebSockets بسيطة (مثل Socket.io) والتي لا تتوسع (Scale) بشكل جيد، يعتمد Septimus OS على بنية تحتية احترافية:
- **Centrifugo**: خادم WebSockets عالي الأداء مكتوب بلغة Go. يتعامل مع ملايين الاتصالات المتزامنة بكفاءة، ويوفر ميزات جاهزة مثل القنوات (Channels) والتواجد (Presence) وإعادة الاتصال التلقائية.
- **NATS**: وسيط رسائل (Message Broker) سريع جداً يستخدم للتواصل الداخلي بين خدمات Backend (مثل Go و Python Sidecar) ولنشر الأحداث إلى Centrifugo.

## 2. نظام القنوات (Channel System)
يستخدم النظام قنوات مخصصة للتحكم الدقيق بمن يستلم أي رسائل:
- `workspace:{workspace_id}`: قناة عامة تصل إليها جميع حسابات مساحة العمل لتحديثات النظام العامة.
- `channel:{channel_id}`: قناة مخصصة لغرف الدردشة الجماعية.
- `user:{user_id}`: قناة خاصة (Private) لكل مستخدم لتلقي الإشعارات الفردية، التنبيهات المباشرة، وتحديثات الحالة.

## 3. التواجد وحالة الاتصال (Online Presence)
- يتم استخدام ميزة `Presence` في Centrifugo لمعرفة من متصل حالياً (Online/Offline) في كل قناة.
- واجهة المستخدم تقوم بالاشتراك (Subscribe) في قنوات التواجد لتحديث الأيقونات (النقاط الخضراء) بجانب صور المستخدمين لحظياً، وتتبع آخر ظهور (Last Seen).

## 4. تدفق العمل اللحظي (Realtime Workflow)
1. **الحدث (Event)**: يقوم مستخدم بكتابة رسالة، أو تحدث طفرة في قاعدة البيانات (مثل تحديث فاتورة).
2. **الخادم (Backend)**: يقوم `backend-core` بحفظ البيانات في PostgreSQL.
3. **النشر (Publishing)**: يرسل الخادم رسالة JSON عبر API إلى `Centrifugo` (أو NATS) موجّهة لقناة معينة.
4. **العميل (Frontend)**: يستلم العميل (المشترك في القناة) الحدث عبر الـ WebSocket، وتقوم مكتبة `Zustand` بتحديث الحالة فوراً ليعكس الـ React التغيير في الواجهة دون الحاجة لإعادة تحميل (Refresh).
